# Continuous Research Engine 0.8

CRE 的核心现在是独立于网页的 Python 引擎。网页、命令行工具或未来的
ChatGPT/Codex 插件都应调用同一套 `ResearchEngine`，不再各自复制研究逻辑。

## 主机需要提供什么

- 两个相互隔离的 `LLMPort` 实例，分别固定承担 A、B 立场；
- 一个 `SearchPort`，生产级深度研究应同时实现 `search` 与 `read`；
- 一个 `StorePort`。独立运行默认使用 `JsonFileStore`，每次有效状态变更都会原子落盘；
- 可选的 `ToolPort`，用于接入 MCP、代码执行或专用数据库等外部能力；
- 可选的 `TranscriptionPort`，把经过筛选的音视频转成带时间戳的论点发现材料；
- 可选的进度回调，供任意前端呈现阶段、立场、Pass 和检查点。

`ResearchEngine.capabilities()` 会返回机器可读的能力清单，并明确指出当前组合距离
生产级深度研究还缺少网页搜索、全文读取或持久化中的哪一项。

## 音视频材料

模型必须先把视频筛成“会改变某条既有论证、揭示前人打法或提供强反例”的候选，才可调用 `transcribe_source`。默认优先读取发布者字幕；没有字幕时使用本地 faster-whisper。每一方每个 Pass 最多转写一个视频，并拒绝超过 90 分钟的单项任务。

转写文本保留时间戳、语言、获取方式和模型身份，作为论点发现材料进入共享来源池。没有说话人标注时不得猜测正反方归属；转写内容也不会因为“来自视频”自动升级成事实证据。已成功转写的来源和本地音轨都会复用，检查点继续时不重复下载或识别。

安装可选依赖：`pip install -e .[asr]`。能力清单通过 `audio_transcription` 告知前端或插件宿主当前是否已接入转写器。

## 稳定调用面

```python
store = JsonFileStore("state/research-001/state.json")
engine = ResearchEngine(
    store=store,
    llm_a=model_a,
    llm_b=model_b,
    search=search,
    tools=optional_tools,
    progress_callback=on_progress,
)

await engine.create(ResearchRequest(
    session_id="research-001",
    question="辩题",
    position_a="正方立场",
    position_b="反方立场",
    profile="deep",
))
await engine.run("research-001")
result = await project_research(store, "research-001")
```

`project_research` 输出 `contract_version: "2"` 的结构化结果，包括双方当前立论、驳论、
已核查证据、来源、论证版本、研究地图、问题档案、Pass 摘要，以及双方当前自主计划和
计划修订历史。网页与 PDF 只是这个统一结果的两种渲染方式。

## 模型自主规划

每一方进入一个新阶段时，运行时先只提供 `update_plan`。模型必须自行解释辩题、判断本方
胜负条件、选择研究路线、列出不超过五个近期行动，并给出何时停止或转向的条件。引擎不替
模型写固定步骤，只强制计划存在、能够修订，并在结束 Pass 前由模型把计划更新为
`ready_to_conclude`。这份计划是可展示、可审计的行动依据，不保存模型的私密思维过程。

搜索失败、对方新版本、关键假设被推翻或原路线收益降低时，模型可以重写路线；预计剩余
行动数是模型根据当前问题作出的滚动预测，而不是引擎写死的工期。

## 运行与恢复语义

- Pass One 的 A、B 两方独立展开；任何一方完成后立即记录阶段检查点。
- 中断后再次调用 `run(session_id)`，只运行尚未提交的立场与阶段。
- 模型生成的非法动作会作为工具错误退回给模型自行修正，不会因此毁掉整场研究。
- 搜索结果只是线索；来源全文读取失败时不会被计入“已核查来源”。同一来源的多条
  EvidenceRecord 也只计作一个已核查来源。
- 达到计算上限只会进入人工审阅，不会伪装成稳定完成；稳定性检查缺少结构化回答时，
  同样不会自动通过。
- OpenAI Responses、OpenAI Chat 和 Anthropic Messages 由统一适配层接入。
  DeepSeek 工具调用需要的 `reasoning_content` 会原样续接到下一轮。

## 当前完成门槛

- `standard`：每方至少形成 3 条证明链完整的核心论点和 2 条针对对方当前版本的驳论；
- `deep`：每方至少形成 4 条证明链完整的核心论点和 3 条针对性驳论，并允许更多修订轮次。

来源数量不再是固定通关指标。模型先靠推理形成有限立论，再为其中真正依赖事实的承重前提
搜索、筛选和深读材料；来源是否足够由证明责任决定。这样既不会用六条来源冒充深度研究，
也不会为了凑几十篇论文而把检索量等价成论证质量。模型仍需完成自己提出的高价值路线，
不能把“以后还应搜索什么”当成最终成果交给用户。
