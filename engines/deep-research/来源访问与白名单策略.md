# 来源访问与白名单策略

## 目标

“白名单”优先解决访问稳定性和任务适配，不代表名单中的内容天然正确，也不排斥名单外的有用观点。引擎把来源分成三个维度独立判断：

1. **论证用途**：发现论点、寻找同题辩论、寻找案例、核验事实。
2. **访问方式**：正式结构化 API、稳定公共网页、普通网页、易失败平台。
3. **证明能力**：观点启发、背景导航、事实证据、原始记录。

论坛、评论、辩论视频可以是很好的论点材料，但不自动证明事实；官方 API 通常更容易稳定读取，但也不自动证明模型从数据中作出的推论。

## 第一批已接入的稳定入口

### Wikimedia / Wikipedia Action API

- 用途：概念、人物、制度背景、公共事件和案例地图。
- 优点：正式 JSON 接口、搜索和纯文本正文均可通过 API 获取，避免抓取网页布局。
- 局限：适合作为导航和背景材料；有争议或决定性的事实仍应追踪其原始出处。
- 文档：https://www.mediawiki.org/wiki/API:Search

### Crossref REST API

- 用途：确认论文、报告和 DOI 的身份与书目信息；有摘要时可读取摘要。
- 优点：无需注册即可访问；正式结构化接口。
- 局限：Crossref 主要是元数据索引。只有元数据时不能据此断言论文结论，缺少摘要时应寻找开放全文或其他记录。
- 文档：https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/

### PubMed / NCBI E-utilities

- 用途：医学、健康、临床、心理和生物医学事实核验。
- 优点：固定 URL 语法和结构化检索/读取接口；不需要网页抓取。
- 局限：只在命名的生物医学事实确实承担论证时调用；文献存在不等于其结论支持辩题。
- 文档：https://www.ncbi.nlm.nih.gov/books/NBK25497/

## 计划作为按需连接器的稳定数据源

- World Bank Indicators API：跨国发展指标和时间序列。应先确定指标、地区和时间范围，再调用，而不用于漫无目的找论点。
- UN、OECD、WHO、Eurostat 及国家统计接口：适合特定公共统计前提，按辩题和指标路由。
- GDELT DOC API：适合发现跨语言新闻案例和公共叙事；它稳定返回新闻索引，但新闻原网页仍可能无法读取，因此属于“稳定发现、读取未必稳定”。

这些入口不应全部塞进每一次搜索。只有当研究地图出现对应事实义务时，才加载相应连接器。

## 运行规则

1. 先立论，再决定是否需要外部材料。
2. 同一任务可以由结构化 API 完成时，优先 API；这是传输策略，不是权威崇拜。
3. 同题辩论、论坛和视频仍可优先用于发现观点。页面无法读取时，只把标题和摘要当线索；寻找一次文字稿或替代副本后即停止。
4. 读取失败与信息不存在分开记录。403、断连、正文过短属于传输失败，不应诱导模型反复改写同一个查询。
5. 每个被保留的来源必须说明它改变了哪个论点、反驳、案例或事实前提。
6. 报告只展示真正进入论证的来源，并明确区分“启发材料”和“事实证据”。

## 创新性要求

Pass One 既要保留让听众能够理解的常规基础，也必须尝试至少一个可辩护的原创推进。原创推进可以来自：

- 改变通常被忽略的比较标准；
- 揭示两个常见现象之间的隐藏因果环节；
- 找到能够迫使对方付出代价的边界案例或两难；
- 把普通直觉组合成新的证明路线；
- 针对预期反驳，重建更窄但更稳的主张。

新奇措辞、冷门材料和故意反直觉都不等于创新。模型必须写清楚“新在哪里、为什么能提高胜率、对方如何可能攻击它”，并把这一项保存到论点结构中。
