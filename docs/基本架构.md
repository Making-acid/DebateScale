# AI 辩论研究与模拟平台——基本架构

## 一、总体分层

```
┌─────────────────────────────────────────────┐
│  前端 UI（类 ChatGPT 三栏界面）                │
│  左侧: 辩题 / Conversation 列表               │
│  中央: 对话流 + 研究过程展示 + 知识查看         │
│  输入框: Tools(/搜索 /深研 /核验) + Mode 切换   │
└──────────────────────┬──────────────────────┘
                       │ SSE / WebSocket 流式
┌──────────────────────▼──────────────────────┐
│  应用服务层（API）                             │
│  Topic / Conversation / Message / Knowledge   │
└──────────────────────┬──────────────────────┘
                       │
┌──────────────────────▼──────────────────────┐
│  引擎层（核心智能）                            │
│  讨论引擎 | 辩论引擎 | 深度研究引擎 | 核验引擎   │
└──────────────────────┬──────────────────────┘
                       │
┌──────────────────────▼──────────────────────┐
│  工具/插件层                                   │
│  搜索 | 深研 | 核验 | 学术/数据库插件 (MCP)     │
└──────────────────────┬──────────────────────┘
                       │
┌──────────────────────▼──────────────────────┐
│  数据层                                        │
│  PostgreSQL(关系+JSONB) + pgvector(知识检索)   │
└─────────────────────────────────────────────┘
```

## 二、技术栈建议

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | React/Next.js + TypeScript | 流式 UI、三栏布局成熟 |
| 后端 | Node.js(TS) 或 Python(FastAPI) | AI Agent 编排二选一，Python 生态更顺手 |
| 数据库 | PostgreSQL + pgvector | 关系数据 + 向量检索（知识库召回） |
| 任务队列 | BullMQ / Celery | 异步深度研究（几十~几百 Steps） |
| 实时 | SSE（讨论）/ WebSocket（研究过程） | 流式输出 + 可暂停 |
| LLM | OpenAI-compatible API 抽象层 | 产品计划 36 节要求 |

## 三、核心模块划分

1. **Topic 模块** — 辩题 CRUD、名称/正反方/说明/备注、工作空间隔离
2. **Conversation 模块** — 对话生命周期、双模式（discussion/debate）、独立上下文
3. **讨论引擎** — 默认模式，普通 LLM 对话 + 可挂载工具
4. **辩论引擎** — Debate Mode：选边、加载 Ruleset、按 StyleProfile 生成 AI 对手、按环节推进、支持局部重赛
5. **深度研究引擎** — 双 Agent 异步对抗研究（核心难点，见下）
6. **工具层** — `/搜索` `/深研` `/核验` 统一为挂载在 Conversation 上的 Tool/Plugin
7. **知识库模块** — 辩题知识 + 跨辩题 Debate Knowledge，Claim 为中心
8. **核验模块** — 来源追溯、证据独立性识别、返回「无法追溯/证据不足/存在冲突」
9. **连接管理** — 模型连接与搜索连接分离（产品计划 36/37 节）
10. **插件系统** — 可插拔数据源/规则/工具，兼容 MCP
11. **成本统计** — Steps / 调用次数 / Token / 搜索次数

## 四、核心数据模型

```
DebateTopic
  ├─ Conversation (mode: discussion|debate)
  │     ├─ Message
  │     └─ ToolCall
  ├─ Knowledge
  │     ├─ Source    原始资料（含来源元数据、证据独立性）
  │     ├─ Claim     可复用的信息（≠ Fact）
  │     ├─ Argument  论点
  │     ├─ Attack    攻击
  │     ├─ Response  回应
  │     └─ Question  未解决问题
  └─ ResearchSession (steps, status, 双 Agent)
        └─ ResearchStep / AgentAction

全局（跨辩题）:
  ├─ DebateKnowledge（方法/技巧/规则/风格模板）
  ├─ Ruleset（环节/顺序/时间/质询/自由辩）
  ├─ StyleProfile（进攻/防守/逻辑密度/事实依赖…）
  ├─ ModelConnection / SearchConnection
  └─ ResearchProfile（快速/标准/重型）
```

## 五、关键设计点

### 1. 深度研究引擎
不是单次搜索总结，而是**可持续的 Research Session 状态机**（暂停/继续/追加 Steps）。双 Agent 交替产生「行动」，用相对判断（还有没有值得继续的方向）而非绝对评分做调度。

### 2. 双 Agent 对抗
`观点 → 攻击 → 对攻击的攻击 → 回应` 的递归结构，允许保留 `Unresolved/Disputed`，不强行达成共识。

### 3. Claim ≠ Fact
知识库最小单位是 Claim，强制关联 Source，并识别「来源关系/证据独立性」防资料污染。

### 4. 长期记忆
Conversation 是历史，Knowledge 是筛选后的长期内容，用户可主动保存、系统可建议。

### 5. 模辩即对话
模拟结束 Conversation 继续存在，复盘、局部重赛、转研究都在同一会话内完成。

## 六、核心产品闭环

```
讨论 → 研究 → 形成认识 → 模拟辩论 → 暴露问题 → 复盘 → 再研究 → 修正认识 → 再模拟
```

没有绝对终点，直到用户走上正式比赛场。
